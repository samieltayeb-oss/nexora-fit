# NEXORA Intelligence Engine™ Specification
*Sprint 4 Implementation Plan*

This document serves as the foundational blueprint for the **NEXORA Intelligence Engine™**. This sprint shifts the project from a polished fitness tracker into a highly differentiated, intelligent ecosystem.

---

## 1. Architecture

The Intelligence Engine is structured in three cascading layers that transform raw telemetry into narrative insights.

### Layer 1: Data Collection (Telemetry)
* **Active Inputs:** Workouts logged, manual weight entries, waist measurements, user notes.
* **Passive Inputs:** Apple Health/Google Fit syncs (future), step counts, active calories, sleep data (future).
* **Storage Model:** Supabase time-series data tables with strict RLS policies. Raw data is never mutated; it is appended.

### Layer 2: Analysis (The Engines)
Data flows from Layer 1 into specialized, single-responsibility analysis engines:
1. `RecoveryEngine`: Analyzes time since last workout and workout intensity to determine readiness state.
2. `PerformanceEngine`: Evaluates volume, load, and personal bests against historical averages.
3. `ConsistencyEngine`: Calculates adherence to the 28-day program and frequency patterns.
4. `GoalEngine`: Projects current trajectory against the target weight/timeline.
5. `TrendEngine`: Identifies macro patterns (e.g., "Waist decreasing despite weight plateau").
6. `RecommendationEngine`: Aggregates the outputs of all engines to prescribe the next best action.

### Layer 3: Insights (Narrative)
The final layer converts the raw analysis into human-readable, coach-like narratives, replacing static data cards with dynamic stories.

---

## 2. Intelligence Modules & Confidence Scoring

Every insight generated by the Intelligence Engine will include an internal **Confidence Score** (High, Medium, Low). The system will clearly communicate its certainty level.

* **High Confidence:** Based on >14 days of consistent, unbroken data. (e.g., "Your strength has demonstrably increased by 12% across 6 sessions.")
* **Medium Confidence:** Based on 3-14 days of data. Trends are emerging but volatile.
* **Low/No Confidence:** Insufficient data. The engine will explicitly state: *"Need 3 more workouts to establish a reliable trend."* It will **never** invent certainty.

---

## 3. AI Guardrails (Strict Compliance)

The NEXORA Intelligence Engine operates under four unbreakable laws:

> [!CAUTION]
> 1. **No Medical Diagnoses:** The system will never diagnose injuries, conditions, or prescribe medical treatments.
> 2. **No Exaggeration:** Tone must remain analytical, objective, and supportive. It will not use hyperbolic language.
> 3. **No Guessing:** If data is missing or corrupted, the system falls back to "Insufficient Data" rather than extrapolating blindly.
> 4. **No Promising Results:** Projections are always framed as *trajectories* based on current habits, not guarantees.

## 4. User Experience (UX) Transformation

### The Narrative Dashboard
The dashboard will be completely redesigned from a static widget grid into a scrolling, story-driven feed:
1. **Morning Brief:** A personalized greeting summarizing the day's objective.
2. **Readiness:** The output of the `RecoveryEngine`.
3. **Today's Workout:** The prescribed protocol.
4. **Progress & Insights:** Contextual analysis (e.g., *"Your weight decreased 0.4 kg while waist improved. You're progressing steadily."*)
5. **My Journey:** A portal to the user's timeline.

### My Journey (The Flagship Feature)
A vertical, cinematic timeline documenting the user's transformation. Every major event (First Workout, Week One, New PR, 5kg Lost) becomes a Milestone card. Milestones can contain:
- Progress photos
- User journal notes
- Automated AI summaries of that specific period

### The Weekly Review
Every Sunday, the system generates a comprehensive summary of the week's inputs (Workouts, Trends, Consistency, PRs) and prescribes recommendations for the upcoming week. This will be formatted as a shareable, exportable report (PDF capability planned).

---

## 5. Performance & Privacy

### Performance
- **Response Targets:** Insight generation must resolve in <300ms on the client.
- **Caching Strategy:** Heavy engine calculations (like historical trend lines) will be computed async and cached in Supabase or a Redis layer, invalidated only when new logs are created.
- **Background Processing:** The Weekly Review will be compiled server-side via scheduled cron jobs to prevent client-side locking.

### Privacy
- **Processing:** Analysis of sensitive health data will occur strictly within the authenticated Supabase edge functions or securely on the client.
- **Data Retention:** Users retain absolute control over their telemetry. Deleting an account triggers a cascading purge of all raw data and derived insights.
